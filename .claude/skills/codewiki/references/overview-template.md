# 仓库总览模板

所有模块文档完成后生成 `overview.md`。仓库总览用于建立导航和系统级理解，不替代模块文档。

## 推荐结构

```markdown
# 仓库名称

## 项目概述

说明仓库用途、主要用户、系统边界和核心能力。

## Maven 结构

根据 `analysis.json.build_system.modules` 总结物理 Maven 模块布局。

## 文档模块

根据 `module_tree.json` 总结顶层文档模块，并链接对应文档。

## 系统架构

使用顶层模块和重要外部系统作为节点。

## 关键流程

描述最重要的端到端请求、事件或任务流程。

## 入口与外部依赖

总结主要 REST API、应用入口、存储、远程服务、MQ、缓存、对象存储和定时任务。只写 artifacts 能支持的内容。

## 文档导航

列出顶层模块文档和重要子模块文档。

## 分析说明

记录 analyzer 诊断、跳过文件、模型聚合边界、无法确认的区域或模块划分限制。
```

## 生成规则

- 架构图以顶层文档模块、Maven 模块或外部系统为节点。
- 每个顶层模块必须有一个主要导航链接。
- 只概括模块职责，不复制模块文档细节。
- 使用 `analysis.json.summary` 说明仓库规模。
- 使用 `build_system.modules` 说明 Maven 结构，即使文档模块按业务域重新聚合。
- 使用 `dependencies.json.module_dependencies` 说明最终模块依赖方向。
- 避免宣传式或推测性描述。
- 如果使用了模型聚合，简要说明聚合依据来自 Maven、包名、Spring stereotype、入口和依赖图。
